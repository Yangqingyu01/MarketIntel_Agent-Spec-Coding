# Feature Specification: 市场情报监测智能体核心工作流

**Feature Branch**: `001-marketintel-core-workflow`  
**Created**: 2026-04-22  
**Status**: Draft  
**Input**: User description: "按照 MarketIntel_Agent_Specify.md 创建市场情报监测智能体的多 Agent 执行规格"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 发起竞品情报分析 (Priority: P1)

企业市场、产品或战略团队成员可以输入一个或多个竞品名称，并在不补充复杂参数的情况下，
获得一份覆盖产品、价格、融资、人才、战略等维度的结构化竞品情报结果。

**Why this priority**: 这是系统的核心价值入口。没有按需分析能力，后续预警、报告和知识沉淀都无法成立。

**Independent Test**: 用户输入单一竞品或多竞品对比请求后，系统可以独立完成目标识别、任务拆解、
信息采集、结构化分析和结果返回，并输出可被前端继续消费的结构化结果。

**Acceptance Scenarios**:

1. **Given** 用户提供单一竞品名称且未指定维度， **When** 用户发起分析请求，
   **Then** 系统使用默认维度与默认时间范围完成一次完整分析并返回结构化情报卡片与摘要。
2. **Given** 用户提供多个竞品并明确提出对比需求， **When** 用户发起分析请求，
   **Then** 系统分别分析各竞品后输出对比结果，并保留各竞品的来源、可信度与关键变化。

---

### User Story 2 - 接收变化预警 (Priority: P2)

企业团队成员希望在竞品出现实质变化时收到分级预警，以便快速判断是否需要产品、市场或销售动作。

**Why this priority**: 预警能力直接决定系统是否能从“被动查询工具”升级为“主动监测平台”，
对持续使用价值影响很大，但它建立在基础分析链路已经可用之上。

**Independent Test**: 当系统对同一竞品存在历史基线时，新一轮分析能够识别实质变化，
根据影响程度分级，并生成去重后的预警事件列表。

**Acceptance Scenarios**:

1. **Given** 某竞品已存在历史基线， **When** 系统检测到与我方直接竞争的新产品功能发布，
   **Then** 系统生成高优先级预警，并附带来源、可信度和建议行动。
2. **Given** 某变化事件在近 30 天内已生成过同类预警， **When** 新一轮分析再次检测到相同事件，
   **Then** 系统跳过重复预警，只保留一次有效事件记录。

---

### User Story 3 - 获取可执行报告与周期摘要 (Priority: P3)

企业管理层和业务团队希望将分析结果转换为可读报告、摘要卡片和图表数据，
用于日常决策、周报汇总和外部工作台展示。

**Why this priority**: 报告与摘要决定情报是否能被真正消费，但它依赖前两条用户故事已经产出稳定、
结构化、可信的情报结果。

**Independent Test**: 系统在收到结构化分析结果后，可以独立生成管理层摘要、维度详情、
行动建议、图表数据以及适配不同终端的输出对象。

**Acceptance Scenarios**:

1. **Given** 系统已完成单一竞品分析， **When** 用户请求查看报告，
   **Then** 系统输出一份包含管理层摘要、维度详情、变化总结和行动建议的结构化报告。
2. **Given** 系统以周期任务方式运行， **When** 到达约定的每日或每周监测时间，
   **Then** 系统自动遍历活跃竞品，生成精简版周期摘要，并仅在存在预警时要求推送。

---

## Edge Cases

- 当用户未指定维度、时间范围或输出格式时，系统如何使用默认值而不阻塞主流程？
- 当目标公司名称存在歧义时，系统如何在最少追问的前提下确认真实分析对象？
- 当某些维度没有近期公开信息时，系统如何继续完成其余维度并明确标记信息缺口？
- 当搜索结果只有摘要、无可抓取全文时，系统如何保留证据来源并标记可靠性下降？
- 当知识库不可用或不存在历史基线时，系统如何降级为冷启动分析而不是中断任务？
- 当图表或终端适配失败时，系统如何保证仍能交付可读的纯文本或结构化报告？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 接收用户输入的竞品分析请求，并提取分析目标、分析维度、时间范围和输出偏好。
- **FR-002**: 系统 MUST 在缺少非关键参数时自动使用默认值，仅在目标对象缺失或存在明显歧义时向用户追问。
- **FR-003**: 系统 MUST 根据任务类型将请求划分为单一竞品分析、多竞品对比、单维度分析或市场扫描四类流程之一。
- **FR-004**: 系统 MUST 将任务拆解为搜索、分析、预警、报告等子步骤，并保留步骤间的依赖关系与执行状态。
- **FR-005**: 系统 MUST 为每个竞品维度生成成组查询，优先采集公开、合法、可追溯来源的信息，并过滤明显无关或不合规内容。
- **FR-006**: 系统 MUST 对采集结果输出统一的结构化原始信息集合，至少包含维度、标题、来源、发布日期、采集日期、内容和初步相关性。
- **FR-007**: 系统 MUST 从原始信息中提取结构化情报条目，并为每条条目标记维度、内容类型、证据片段和实体信息。
- **FR-008**: 系统 MUST 为每条可用情报计算可信度评分，并基于来源级别、交叉验证、时效性和一致性处理得出最终分值。
- **FR-009**: 系统 MUST 明确区分 `fact`、`inference`、`unverified` 和噪声内容，不得将推断伪装为已确认事实。
- **FR-010**: 系统 MUST 在存在历史基线时执行变化检测，并仅对有证据支撑且可信度达到最低阈值的实质变化生成变化事件。
- **FR-011**: 系统 MUST 在不存在历史基线或知识库暂不可用时以冷启动模式运行，并明确标记本次结果未执行历史对比。
- **FR-012**: 系统 MUST 按预定义规则为变化事件评估预警等级，并避免在短期内对同一事件重复生成预警。
- **FR-013**: 系统 MUST 将分析结果转换为报告输出，包含管理层摘要、维度详情、变化总结、数据质量说明和可执行行动建议。
- **FR-014**: 系统 MUST 支持面向不同终端的结构化输出形态，包括 Web 侧数据对象和消息卡片摘要对象。
- **FR-015**: 系统 MUST 在每轮任务结束后输出用户可理解的进度与结果摘要，并对失败步骤采用定义好的降级方案而非整体中断。
- **FR-016**: 系统 MUST 定义定时监测流程，对活跃竞品执行周期扫描、生成周期摘要，并只在需要时要求立即推送预警。
- **FR-017**: 系统 MUST 记录可持久化的情报快照、预警记录和工作空间级配置，以支撑后续基线对比和去重判断。
- **FR-018**: 系统 MUST 确保所有最终输出都可追溯到公开来源，并以简体中文向中文企业用户呈现主要内容。
- **FR-019**: 系统 MUST 定义当某维度无结果、全文抓取失败、结构化提取失败、图表生成失败或推送失败时的标准降级行为。
- **FR-020**: 系统 MUST 保持各 Agent 的职责边界，避免搜索、分析、报告、预警能力相互越权或跳过编排链路。

### Key Entities *(include if feature involves data)*

- **任务请求**: 一次由用户或定时任务触发的分析任务，包含目标、维度、时间范围、输出偏好和执行模式。
- **竞品对象**: 被监测的公司或产品实体，包含名称、别名、所属行业和监测配置。
- **原始搜索结果**: 由搜索阶段返回的公开来源条目，保留标题、链接、来源、发布日期、抓取内容与相关性。
- **结构化情报条目**: 由分析阶段提取的可消费信息单元，包含维度、内容类型、证据片段、可信度和实体字段。
- **历史基线快照**: 某竞品在某一时间点的已验证情报集合，用于后续变化检测。
- **变化事件**: 与历史基线相比识别出的实质性变化，包含变化类型、维度、描述、严重程度和证据。
- **预警事件**: 经过去重和分级后可供通知或汇总的事件对象，包含严重程度、推送时机和建议行动。
- **情报报告**: 面向用户消费的结果对象，包含摘要、维度详情、图表数据、行动建议和数据质量说明。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 90% 以上的标准竞品分析请求可以在一次提交后直接进入执行，无需用户补充非关键参数。
- **SC-002**: 对于存在有效公开来源的分析请求，系统能够为每个被分析竞品输出至少 1 条带来源和可信度的结构化情报。
- **SC-003**: 100% 的核心结论都能追溯到公开来源，且结果中不存在未标记来源的事实性陈述。
- **SC-004**: 在存在历史基线的情况下，系统对实质性变化的预警结果中，重复预警率低于 5%。
- **SC-005**: 80% 以上的用户在查看单次分析结果时，可以直接从输出中获得明确的下一步业务动作建议。
- **SC-006**: 当某个子流程失败时，系统仍能在 95% 以上的任务中返回部分可用结果，而不是整单失败。

## Assumptions

- 用户已在系统中配置或能够提供需要监测的竞品名称与基本别名信息。
- 默认分析时间范围为近 3 个月，默认维度为产品、价格、融资、人才、战略五类。
- 系统只处理公开合法来源，不覆盖登录后私有数据、付费墙内容或非授权内部信息。
- 中文企业用户是主要使用人群，因此主要输出默认采用简体中文。
- 工作空间中存在或将存在可供查询的竞品配置、历史快照和预警记录存储能力。
- 周期监测任务由调度器触发，具体调度能力本身不作为本 feature 的独立建设范围。
